## 三、复现方法

脚本已收进 `tools/smoke/`（从 `C:\Users\肖铭俊\AppData\Local\Temp\claude\` 拷入，原始工作副本仍在该目录）：

```bash
# 0) 前置：后端 + 前端已启动，CDP Edge 打开 http://localhost:5276/?demo=1
cd tools/smoke
node reset_demo.cjs          # 清 localStorage/sessionStorage 后重载到干净演示态
node screen_rec.cjs EF426E15 run_dir 40 85 &   # 后台录屏到 run_dir/

node encode_video.cjs run_dir 输出.mp4        # 编码最终视频
```

要点（踩坑记录）：
- 游览会话持久化在 `localStorage['lingshan-tour-session']`，页面重载会被 TASK-09 恢复游览，但**不会**自动重启位置模拟 → 每次冒烟前必须 `reset_demo.cjs`。
- 演示位置模拟只在「开始游览」后启动；演出提醒依赖演示时钟（取最近有演出景点的首场前 10 分钟），首站选有固定场次时刻的景点（九龙灌浴）可稳定触发。
- 驱动轮询演出卡需遍历所有 `.msg.notice .notice-text`——`querySelector('.notice-text')` 只取第一条通知卡（可能被「已到达」卡挡住）。

## 四、已知限制（如实标注，不掩盖）

1. **语音输入用文字代替**：CDP 无法向浏览器注入麦克风音频流，冒烟测试以聊天框文字模拟语音问句；音频→文字的语音识别链路未在此次录屏中覆盖。
2. **演示模式数据**：位置模拟（每 8s 进一站）与演示时钟均为 `?demo=1` 下的模拟值，页面有「🎬 演示模式」标识；admin 统计为真实后端数据。
3. **自动讲解抢占**：聊天朗读未结束时到达，自动讲解会被「忙碌」守卫跳过，转为「已到达」提示卡（本轮前两站即此情况）——产品预期行为。
4. **Edge-TTS 403 已知问题**：朗读若返回 403（区域受限），会静默降级为纯文字卡片，不影响其他功能。
5. **proactive 通知截断**：同一时刻到达+下一站提示同时触发时 `out.slice(0,2)` 可能挤掉演出卡；视频中演出卡已在窗口内稳定出现，未受影响。
